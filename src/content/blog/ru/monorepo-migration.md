*В прошлом посте мы закончили на «один слой — один репозиторий». Правило изменилось: официальные слои теперь живут каталогами в одном дереве. Всё остальное в архитектуре осталось на месте.*

В августе мы рассказали, как 71-шаблонный C#-монолит разобрали на четыре независимых репозитория и как N вариантов персистенции × M вариантов транспорта дают N+M репозиториев ([От монолита к осям и слоям](https://fellmonkey.github.io/domaincraft-site/ru/blog/bridges-axes-layers/)). Математика осталась. Изменилась упаковка: девять официальных мостов теперь лежат в репозитории ядра под `bridges/`, а бинарь, собранный из этого репозитория, несёт их в себе.

## Что переехало

```
DomainCraft/
  cmd/  internal/  spec/          # ядро
  bridges/
    csharp/
      core/
      domain/
      persistence/efcore/
      persistence/dapper-stub/    # эксперимент, нет в реестре
      transport/rest/
    typescript/
      core/
      client/
      react/
    admin/
    appwrite/
```

В реестре девять мостов: четыре C#-слоя, три TypeScript-слоя, админка, Appwrite. Рядом лежит Dapper-stub — эксперимент, которого нет в реестре. Устаревший ID `csharp-restful` остался в реестре для совместимости, но каталога для него в дереве нет.

| | До | После |
|---|---|---|
| Официальные мосты | 9 отдельных репозиториев | 9 каталогов под `bridges/` |
| Поиск базового моста в `extends:` | догадка по имени репозитория и соседним папкам | поиск `Path` в реестре |
| Флаг `--bridge` | сначала кэш или удалённый репозиторий | локальное дерево → встроенная копия → удалённый репозиторий → кэш |
| Версия контракта | отсутствовала | `contract_version` в `bridge.yaml` |
| Использованная комбинация мостов | не фиксировалась | `domaincraft.lock.json` |

## Проблема была в поиске путей, а не в папках

Раньше базовый мост находили по имени GitHub-репозитория: брали имя вроде `domaincraft-bridge-csharp-core` и искали соседнюю или вложенную папку. В раскладке `bridges/csharp/core/` оно уже не совпадает с каталогом. Эвристика не пережила переезд: имя папки и ID моста перестали быть одной строкой.

Была и вторая проблема. Флаг `--bridge` обходил мосты в другом порядке, чем ссылки `extends:`. Запустите генерацию внутри монорепо с `--bridge csharp-rest` — и CLI взял бы копию из кэша или удалённого репозитория вместо локального дерева. Переезд поменял бы папки, но не поведение. Теперь обе точки входа идут в одном порядке: локальный `bridges/<path>` → встроенная копия → удалённый репозиторий → кэш.

Проверка локального пути теперь общая: `bridge.LocalBridgePaths` используется и в механизме разрешения, и в рендерере. Путь, который указывает на отсутствующий каталог или на папку без `bridge.yaml`, считается ошибкой, а не поводом обратиться к удалённому репозиторию.

## Одно правило: ID → каталог

В `RegistryEntry` появились три поля — `Path`, `Layer`, `Deprecated`. `OfficialPath(id)` — единственный источник правды; никакой механизм не выводит путь из имени папки. Объявление стало данными:

```go
{
    ID:    "csharp-efcore",
    Path:  "csharp/persistence/efcore",
    Layer: "persistence",
}
```

Файлы `bridge.yaml` оставили `extends:` в виде ID, поэтому при переезде не изменился ни один из них. `Layer` должен совпадать со значением `layer:`, которое объявляет сам мост, иначе `--replace persistence=…` попадал бы не в тот мост, который заявлен в документации. `Deprecated` оставляет старый ID доступным, но не предлагает его в интерактивном меню.

## Мосты внутри бинарника

`go:embed bridges` компилирует официальное дерево в бинарник на этапе сборки. Отдельного шага выпуска не нужно: сборка из тега встраивает шаблоны именно этого коммита. Загрузчик читает сначала локальное дерево, затем встроенную копию, затем удалённый репозиторий и кэш. Установка через `go install ...@latest` генерирует код без сети уже при первом запуске.

Встроенную копию переносят в кэш мостов. `internal/bridge/embed.go` проверяет каждый компонент пути на символические ссылки: подложенная ссылка не должна вывести запись за пределы кэша.

## У контракта появилась версия

В `bridge.yaml` появился `contract_version`. Ядро объявляет версию, которую реализует. Мост, который запрашивает более новую версию, получает ошибку с обоими номерами. Мост без поля считается контрактом v1 с предупреждением об устаревании — старые мосты продолжают работать. Строка `version:` теперь парсится; раньше её молча игнорировали.

Золотой тест в `internal/contract` рендерит фиксированный `domain.yaml` и сравнивает вывод побайтово. Он покрывает четыре самодостаточных моста: `csharp-core`, `ts-core`, `admin-alpine`, `appwrite`. Ограничение честно записано в исходнике теста: составные цепочки вроде `csharp-rest → … → csharp-core` пока не покрыты. Нужен механизм разрешения, который живёт в `cmd/domaincraft` и не импортируется из пакета контракта.

Рендерер теперь прерывает работу на неизвестном условии `when:`, а не рендерит шаблон без проверки. Мост не может незаметно получить новый файл из-за опечатки в условии.

## Файл `domaincraft.lock.json`

Файл пишется рядом с `domain.yaml`. В нём перечислены реально использованные мосты: `id`, каталог `path` в монорепо или удалённый источник `source`, `version`, `contract_version`. Записи отсортированы по ID и не несут временных меток, поэтому изменения в файле легко читать при ревью.

Снимок помнит, какой была модель. Файл фиксации помнит, какие мосты её собрали. Когда приходит сообщение «перегенерация изменила файлы», эти два файла отделяют изменение модели от изменения моста.

## Что не изменилось

`domain.yaml` не изменился. Команда генерации не изменилась. Под монорепо не добавили ни одного флага. Файлы на выходе побитово идентичны до и после переезда: формат снимка, набор функций шаблонов и сам вывод не тронули. Девять репозиториев стали каталогами. Контракт не сдвинулся.

## Что это даёт

Новый слой — это каталог плюс строка в реестре, а не новый репозиторий, который нужно подключать. Комбинирование слоёв по-прежнему идёт через `--replace`: флаг выбирает узел, реестр его находит.

Ограничения остались теми же, что до переезда. Сегодня поставляется девять мостов. gRPC и Vue — в планах. Для Go, Java и Python мостов нет. Сборка всего в одном дереве эти мосты не напишет; она лишь означает, что когда они появятся, они лягут рядом с остальными.

Команда осталась прежней:

```bash
domaincraft generate --domain domain.yaml --bridge csharp-rest
```
